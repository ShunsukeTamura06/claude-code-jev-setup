# Jev execution routing

- Claude workerを開始する前に、Jev MCPを1回呼び出し、実行方針を選択させる。
- 同一セッション内ではmodelを原則固定する。セッション途中でmodelを切り替えるルーティングは避ける。
- Jevは主に現在のmodelに対するeffortレベルを選択する。明確なコーディングタスクではmediumを基本とし、複雑な推論や厳密な構造化出力が必要な場合はhighまたは利用可能なより高いeffortを選ぶ。
- Jevの選択結果が無効、取得不能、または低信頼の場合は、現在のmodelとホストのデフォルトeffortを使用する。
- より強いmodelが本当に必要な場合は、現在のセッションのmodelを切り替えるのではなく、別Claude workerを起動する。
- 別Claude workerは、複雑な独立推論、独立調査、またはユーザーが明示的に要求したレビューが必要な場合にのみ使用する。
- 別Claude workerには会話履歴全体を渡さず、タスク、対象ファイル、必要なコンテキスト、制約、完了条件だけを明示して渡す。得られた結果と根拠はメインセッションへ返す。
- 各セッション開始前にmodelとeffortを確定し、そのセッション中は固定する。権限と承認はホスト側が管理する。
- ユーザーが依頼していない機能、テスト、ファイル、ドキュメント、リファクタリング、追加レビューを勝手に増やさない。
- 作業完了前に、変更を検証できるテスト、build、type check、または確認コマンドを実行する。実行不能なら不足している確認手段と理由を明示する。
